# 拼豆实验室

面向负责人和实习生的实验管理工作台。使用原生 Node HTTP、SQLite 和浏览器 ES modules，复用仓库已有的 pngjs，无额外前端依赖。

## 当前能力与边界

已实现真实服务端存储和权限：账号、任务创建/分派/领取、关卡单参数与背景 PNG 候选、不可变资源、冻结基线、A/B 静态预览、自测记录、提交/退回/单项和批量审阅、手动排期与流量互斥、本地分组/事件验证、结果计算、复盘归档、审计记录。

**当前环境仅用于本地验证，不接入线上游戏。** 启动实验只改变工作台验证接口返回的配置，不修改游戏关卡、CDN 或云函数。新增受限的本机浏览器试玩入口，试玩记录独立保存，不能据此判断线上实验胜负。正常启动不注入示例任务、默认账号或模拟指标。

尚未实现：生产配置发布和回滚适配器、生产客户端自动分组/曝光接入、引导/地图/音频模板、真机试玩入口、自动定时排程、扩大已运行实验流量、线上留存/商业指标聚合、通知渠道。现有游戏 CRC32 与通用日报的旧字段口径也未在本改动中迁移。不可把当前后台视为生产实验平台已交付。

## 启动

在游戏仓库根目录执行：

```sh
npm run ab:admin
```

访问 http://127.0.0.1:4318。首次打开由使用者自行创建负责人账号，密码至少 12 个字符；负责人在“团队与记录”添加成员。

已验证运行时为 Node 25.8.2；需要提供内置 `node:sqlite` 的 Node。依赖沿用根目录的 pngjs。

可配置环境变量：

| 变量 | 说明 |
| --- | --- |
| PDD_AB_PORT | 本机服务端口，默认 4318 |
| PDD_AB_DB | SQLite 数据库绝对路径，默认 local/experiment-admin/workbench.sqlite |
| PDD_AB_ORIGIN | 可选的 HTTPS 共享 origin；需先在本机初始化负责人，再配置反向代理 |

数据保存在 Git 已忽略的 local/ 目录，不使用 localStorage 存储业务数据。账号密码使用独立随机 salt 的 scrypt；会话 token 只保存 hash，Cookie 为 HttpOnly、SameSite=Strict，12 小时过期；修改密码或禁用成员时撤销会话。

## 团队共享访问

默认仅绑定 127.0.0.1。让几名成员访问同一个工作台，需要将该服务放在团队服务器上，通过已有 HTTPS 反向代理转发至 127.0.0.1:4318，并配置 PDD_AB_ORIGIN 为实际的 HTTPS origin。代理必须保留外部 Host；浏览器 Origin 与配置不一致会被拒绝，HTTPS origin 下会话启用 Secure。

初始账号必须先经本机地址创建。空数据库配置共享 origin 会拒绝启动，避免暴露无人认领的初始化入口。本次没有创建公网入口或部署代理。

采用一个 Node 服务进程处理小团队协作；SQLite 开启 WAL 和事务。当前业务状态作为一个 JSON 文档保存，适合有限规模的管理与协议验证，不能作为高流量生产事件仓库。生产接入前需拆分事件/分配表、增加分页及服务身份鉴权，并完成容量测试。

备份时先正常停止服务，再复制数据库及尚存在的同名 -wal/-shm 文件；不要在线只复制主文件。恢复使用 PDD_AB_DB 指向备份副本。启动不会掩盖数据库损坏或版本不兼容。

## 推荐操作路径

1. 负责人创建成员。创建任务，选择关卡、唯一变量、样本、观察窗口、最短天数和失败率护栏。
2. 指定成员，或将任务留待领取。领取在服务端事务中校验，第二人不能抢占已领取任务。
3. 成员创建候选。A 组读取本地关卡完整快照，B 组只修改白名单中的一个参数；背景任务需先上传 A/B 图片。
4. 查看 A/B 内容预览，并填写实际自测步骤和证据位置。静态预览不会自动产生曝光，不等同于客户端试玩。
   可在详情中生成“实际游戏试玩”入口，按下方步骤检查；只有后台收到对应记录才算连接成功。
5. 提交后锁定内容。负责人单项或逐项勾选批量审批。批量接口逐项返回成功/失败，旧版本、失效基线不能通过。
6. 负责人设置团队流量预算，对待排期实验启动本地验证。同关卡已有运行或观察中实验时拒绝启动。
7. 使用“验证分组与事件”手动检查稳定分配和事件协议。此处事件全为本地测试数据，不能混为正式玩家曝光。
8. 停止新增入组后等待现有用户观察窗口结束；填写复盘后由负责人确认归档。

共享编辑采用实验版本号校验，陈旧操作返回 409；点击“刷新数据”后重新查看。没有在填写过程中自动覆盖草稿。

## 本机实际游戏试玩

1. 用 Cocos Creator 3.8.8 打开当前仓库，刷新新脚本后启动浏览器预览。后台不负责启动或刷新编辑器。
2. 在实验详情生成试玩入口，输入本机 HTTP 根地址（例如 http://127.0.0.1:7456/），选择 A 或 B。每个链接只允许一个实验的一组，1 小时有效，最多保留 20 个有效链接，可撤销。
3. 打开链接。客户端读取冻结的整关数据，B 组只替换唯一参数；背景任务校验图片 hash、尺寸、解码并应用到既有背景 Sprite。背景实验要求个人装备为默认背景，冲突时显性停止。
4. 返回后台，关闭详情、刷新数据再打开。会分别显示配置加载、实际展示、通关或失败。没有连接记录时不能把画面当成候选验收；应检查 Cocos 是否刷新到了新脚本。

试玩 token 位于 URL fragment，不复用管理 Cookie。API 仅允许签发时的本机来源，校验有效期、撤销、签发成员状态和候选内容指纹；修改候选后需要重新签发。导出包含独立试玩记录，不含 token 或 token hash。

源码接入在实际可交互时上报展示、gameWin 时上报完成；曝光必须先于完成，重复事件幂等。此功能用于内部自测，不提供反作弊保证。试玩抑制正式 Analytics 上传、通关进度与通关金币奖励；倒计时使用冻结配置，避免 DDA 干扰。它不是独立游戏存档沙盒，其他道具和设置仍使用本机预览存储，建议用专用测试浏览器。

**当前验收状态（2026-09-08）：** 试玩 API、客户端协议测试和入口生成界面已通过。本机 Cocos 尚未刷新编译缓存，B 组仍显示旧容量 60，后台无连接事件；真实容量 66、背景绘制及完整通关回传仍待刷新后验收，不能宣称已完成端到端验证。

## 数据与统计约定

- 用户 ID 仅用于验证接口，服务端保存其 SHA-256；交通桶与实验组分别使用确定性 SHA-256 分配。该 v1 验证协议**不是现有游戏 CRC32 协议的替代品**，不能直接套用到线上老用户。
- 100 个流量槽位在运行/观察实验之间互斥；同一验证用户一旦参与实验，不再进入下一实验。观察结束前不释放槽位。首版不支持扩量。
- 实验启动冻结 configHash，事件必须携带对应分配 ID 和 hash。幂等 ID 重放内容不一致返回 409；没有曝光不能上报完成。
- 事件时间使用服务端接收时间，不支持离线补报。超过用户观察窗口拒收；当前结果只比较成熟用户。
- 分配、曝光、失败、成熟样本和完成数分开显示，失败用户保留在分配分母中。完成率使用成熟分配用户，不按曝光成功者过滤。
- 每组至少 20 人后检查失败率护栏；分组比例使用等比例卡方阈值 10.83。异常时停止新增入组并记录原因，已有用户仍可完成观察。
- 差值区间使用 Wilson 分组区间组合的 Newcombe 95% 区间。样本和最短运行周期未满足时不给正向结论；即使满足，也只标记“本地验证正向，需正式复验”。样本目标由负责人确定，不是自动功效计算。
- 暂停/终止不是隐式切回 A；终止后验证分配接口不再返回此实验配置，保留历史记录。本地工作台没有生产游戏的回滚执行能力。
- 页面日期统一 Asia/Shanghai。来源、成熟度和失败情况明确展示；没有真实数据时不生成结果。
