# 前期关卡候选 v1

本目录为独立评审稿，未替换 assets/LevelData 正式关卡。

打开 http://localhost:8080/tools/generated_levels/retention-v1/ 查看原版、候选和目标图案，并进入 Cocos 7456 试玩。

若试玩先显示 UI Preview，点击「进入 Game.scene」即可进入对应候选。

## 设计

| 关卡 | 原错位数 | 候选错位数 | 待操作颜色 | 本关目标 |
|---|---:|---:|---:|---|
| 3 | 251 | 108 | 3 | 从第二关的72颗平滑过渡，巩固腾空位置和轮换颜色 |
| 4 | 456 | 144 | 3 | 保持已学颜色规模，增加处理量 |
| 5 | 511 | 180 | 4 | 引入更多颜色选择，观察传送带余量 |

使用连通的六颗色块成对交换，保留目标图案、颜色数量、计时和容量；已归位豆豆锁定，减少同时需要决策的位置。本版偏易，重点验证前期难度跃迁能否缓和，不预设留存收益。

首关已在源码中复用 v3 的 guang_quan 光圈：当前步骤的可操作豆豆发光，手指指向真实豆豆，空白与已归位豆不推进步骤，切换及结算时清除光圈。

## 验证与限制

- 三个候选分别运行现有规则的五种种子机器人，各5/5找到无需道具的合法通关路径；参考操作见 solution_N.json，行列从0开始。
- 机器人使用 PvpBotReplay 的保守1倍速时序；它证明可解，不代表真人通关时间、成功率或广告需求。
- 试玩入口是外部关卡，不包含主线专属引导、第三关免费+12扩容、动态难度调整。要评估真实主线数据，后续需将批准候选接入独立实验桶。
- generate.cjs 基于当前源码重建候选与证据；manifest.json 保留正式原文件 SHA256，供核对。
- 尚未经过真机体验与线上A/B；广告触发规则保持当前版本。
- 首关浏览器360px预览已验证空白/已归位豆不推进、两步有效点击通关及提示清理；第三关候选已在真实游戏预览加载。
- 本次4项相关测试及TypeScript检查通过。另有first-level-guide-ui和first-level-guide-transition-preview两项现有测试失败，用修改前HEAD控制器复跑同样失败，未将其记作通过或扩大修改。

## 试玩观察与后续实验

观察能否一眼找到可操作豆、是否理解“为另一种颜色腾位置”、是否因等待传送带感到无事可做，以及第三关是否过于简单。不要以机器人耗时制定目标。

建议分开验证首关提示与3—5关布局，避免混淆效果。比较同版本、同来源的新玩家：引导完成率、下一关进入率、失败后继续率、次日留存，以及每新增玩家累计广告完成数/收入。广告请求、填充、播放、完成分别统计；短会话自然结束不直接计作流失。样本量根据基线和希望检测的改善幅度决定。

若通关提升但广告下降，应先比较玩家后续关卡与次日累计收入，再决定是否回调难度；不得只为增加单关广告而恢复前期卡点。
