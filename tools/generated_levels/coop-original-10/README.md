## 文件
- `preview.html`：浏览器打开即可审阅完整图案、分享时半成品效果及初始乱序；不依赖网络。
- `contact-sheet.png`：总览，自左向右第一排 1–5 关，第二排 6–10 关。
- `assets/LevelData/coop_level_1.json` 至 `coop_level_10.json`：正式关卡真源，沿用 LevelData 核心字段，使用正式 20 色 ID。
- 同名 PNG：完整图案的像素预览；预览背景不是有效豆豆。
- `assets/GameAssetsBundle/coop-manifest.json`：图案名称、唯一图鉴标识、分区、种子、数量和关卡文件 SHA256。
- `validation.json`：数据校验及 20 个半区的通关回放结果。
- `solution_<关卡>_<0或1>.json`：发起者或合作者半区的合法操作序列，坐标为裁切后的 32×56 半区局部坐标。

## 分区与接入约束
发起者拥有列 0–31，参与者拥有列 32–63，均含端点。每条分享下的不同参与者分别复制右半区初始状态，独立存档，不共享右半进度。
合作运行时需按配置隔离半区模型；不能把整图直接交给现有单人规则后只禁用半边点击，否则连选和归位仍可能跨区。
左半已完成且某位参与者右半完成后，发起者与该参与者解锁对应 `collectionId`，按账号与图案去重。现已接入本地合作实现，发布配置及验证边界见 `docs/coop-mode.md`。
`levelId` 为合作候选目录内编号，不代表覆盖原主线或像素关卡；不得写入原 `themes.json` 后当单人关卡发布。

## 参数与验证
- `Hard: 0`、`slotTotalCount: 12`、`conveyorCapacity: 60`；单次选取沿用默认 12。
- `timeLimit: 600` 为离线求解和预览参数，不代表已确定正式合作计时策略。
- 初始乱序复用 `tools/shuffle-comparison.js`，每个半区分别生成，颜色守恒、轮廓不变、零初始归位。
- 20/20 半区均通过当前 TypeScript 棋盘及传送带规则的合法操作回放，无道具、容量不超过 60，终局目标全部锁定且缓冲区为空。
- 求解器用时约 167–398 秒，是高熟练度机器人规则模拟结果，不是玩家平均用时或难度平衡证明。
- 未进行 Cocos 合作页面、真机性能或多人云端流程验收。

## 复现
在 game-pdd-v2 根目录依次执行：

```sh
node tools/generate-coop-levels.js
node tools/verify-coop-levels.js
```

原创图案由网格绘图指令生成；未复制已有角色或旧关卡图案。乱序工具的参考关卡只用于既有算法参数。
