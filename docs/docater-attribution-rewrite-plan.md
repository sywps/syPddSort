# 轻松拼豆投放数据系统建设方案

> 会议讨论版  
> 日期：2026-06-18  
> 适用对象：`轻松拼豆 / 拼豆豆` 微信小游戏、IAA 广告变现、腾讯广告 / 广点通 / adQ 投放  
> 文档目标：从零设计一套面向未来 12 个月的投放数据系统，而不是重构旧系统。旧 `docater1` 仅作为历史参考，不作为主方案依据。

## 0. 先说结论

我们要建设的不是一个“广告报表导入工具”，而是一套能把投放、素材、游戏版本、AB 实验、用户行为、广告收入、长期 ROI 串起来的数据系统。

这套系统的核心任务是回答五个问题：

1. 腾讯 adQ 平台给了我们什么数据。
2. 游戏内哪些关键行为必须我们自己埋点。
3. 素材、投放批次、游戏版本、AB 实验之间如何建立业务关系。
4. 首日、3 日、7 日、30 日、90 日 ROI / LTV 怎么看，哪些指标只适合短期诊断，哪些指标决定长期回本。
5. 什么时候应该继续优化产品，什么时候应该换素材，什么时候可以从朋友圈基准测试进入智投、视频号、直玩、试玩或更大规模放量。

当前最重要的认知是：

- 拼豆类微信小游戏不是短周期快速回本模型，而是依赖长期留存和 IAA 广告变现的长周期模型。
- 冷启动阶段最重要的不是快速放量，而是建立干净、可复盘的基准链路。
- 第一阶段建议围绕 `竞价广告 3.0 + 手动朋友圈版位 + 视频 / 图片素材` 建立基准。
- `竞价广告 3.0 / 智投 / AIM+`、`朋友圈 / 视频号 / 激励视频 / 搜索场景`、`视频 / 图片 / 直玩 / 试玩` 是三个不同维度，不能混在一起判断。
- 腾讯 adQ / Marketing API 能提供投放对象、素材、报表、消耗、资金、转化回传能力；但用户进入游戏后的真实行为、首局体验、广告点触发、AB 实验分组，必须由我们自己的埋点系统负责。
- `docater1` 是历史老系统，只放到附录，用来提醒过去有哪些字段和坑，不进入新系统主架构。

## 2. 这套系统要解决什么问题

我们要建设的是一套“投放实验与游戏增长数据系统”。它不是单纯的 adQ 报表同步，也不是单纯的游戏埋点，更不是 `docater1` 的重写。

它需要同时支持三类工作：

1. 投放侧：知道每一笔钱投到了哪里，买来了什么流量，哪个计划、版位、素材、投放方式有效。
2. 产品侧：知道这些流量进入游戏后，到底在哪一步流失，首局是否理解，广告点是否触发，留存和长线价值是否成立。
3. 实验侧：知道某个素材、某个游戏版本、某个 AB 实验和投放结果之间的关系，避免把素材问题误判成产品问题，或把产品问题误判成流量问题。

一个合格的数据系统，至少要能回答：

- 这次消耗来自竞价 3.0、智投、AIM+，还是其他投放方式？
- 这次消耗来自朋友圈、视频号、激励视频、搜索场景，还是其他版位？
- 这批用户看到的是视频、图片、直玩，还是试玩？
- 用户进来后是否看到了和广告承诺一致的首屏？
- 用户是否在 10-30 秒内理解玩法并完成第一次有效操作？
- 首局失败、复活、奖励、广告点是否形成健康结构？
- 素材表现不好，是外层点击差，还是点击后首局承接差？
- ROI 低，是买量贵，还是进入游戏后的广告完成少，还是留存周期不够？
- 当前首日、3 日、7 日指标能否支持继续观察到 30 日、90 日？
- 哪些素材、计划、版本、实验值得继续，哪些应该淘汰？

## 3. 拼豆类 IAA 微信小游戏的投放背景

拼豆类小游戏的投放判断，不能用短平快买量游戏的口径。

根据内部 Wiki 和当前市场反馈，拼豆类 IAA 微信小游戏具备一定买量空间，但更偏长周期广告变现模型。它不是“首日或 7 日快速回本”的模型，而是依赖用户持续留存、持续玩、持续看广告，最终在 30 日、60 日、90 日回收价值。

内部 Wiki 给出的参考节奏是：

| 时间 | 累计 ROI 参考 | 使用方式 |
| --- | ---: | --- |
| 首日 | 7%+ | 看冷启动基础质量，不判断最终回本 |
| 3 日 | 13%-14% | 看短期爬坡是否正常 |
| 7 日 | 18%-19% | 看早期留存和广告变现是否继续释放 |
| 30 日 | 接近 40% | 判断是否有长周期价值 |
| 90 日 | 观察最终回本可能 | 判断模型是否真正成立 |

这意味着：

- 首日 ROI 不是最终答案，但首日过低会提示素材承诺、流量质量、首屏承接、首局体验或广告点设计有问题。
- 7 日不回本并不等于产品失败，但 3 日、7 日爬坡明显弱，通常需要看留存、关卡节奏、广告点触发和长线目标感。
- 30 日和 90 日才更适合判断拼豆类 IAA 模型是否具备长期回本可能。

## 4. 三层概念必须分开

投放讨论中最常见的问题，是把投放方式、广告版位、素材形态混在一起。新系统和会议讨论必须先统一这三层。

| 层级 | 示例 | 说明 |
| --- | --- | --- |
| 投放方式 | 竞价广告 3.0、智投、AIM+ | 系统怎么投、由谁控制变量、模型如何优化 |
| 广告版位 / 流量场景 | 朋友圈、视频号、微信公众号与小程序、小游戏激励视频、搜索场景 | 广告展示在哪里，用户为什么会看到 |
| 素材形态 / 广告体验 | 视频、图片、直玩、试玩 | 用户看到什么内容，用什么形式被吸引 |

正确表达应该是组合式的，例如：

- `竞价广告 3.0 + 朋友圈 + 视频素材`
- `竞价广告 3.0 + 朋友圈 + 图片素材`
- `智投 + 系统自动分配流量 + 视频/图片/其他素材`
- `竞价或专项投放 + 直玩素材`
- `竞价或专项投放 + 试玩素材`

错误表达包括：

- 把朋友圈说成直玩。
- 把智投和朋友圈并列。
- 把竞价广告 3.0 理解成 ROI 3.0。
- 把视频、图片、直玩、试玩当成同一种测试。

当前内部 Wiki 的关键口径是：

- 冷启动第一阶段优先做 `竞价广告 3.0 + 手动朋友圈版位 + 视频 / 图片素材`。
- 当前朋友圈版位不应混同为直玩或试玩测试。
- 直玩和试玩需要作为后续独立素材形态测试，不应混进朋友圈基准测试结论。

## 5. 冷启动阶段的核心原则

第一阶段不是为了快速花钱，也不是为了马上找放量模型，而是为了建立干净的基准数据。

冷启动阶段应该遵循：

1. 变量少：先固定投放方式、版位、人群范围，避免同时混多个渠道和素材形态。
2. 数据干净：优先能解释问题，而不是追求最大消耗。
3. 产品优先：第一阶段核心是验证产品模型和首局承接，不是只选素材。
4. 长周期视角：首日只看基础质量，不能直接判断最终回本。
5. 可复盘：每轮投放必须能说明测了什么、固定了什么、结果意味着什么。

如果冷启动一开始就混入朋友圈、视频号、激励视频、智投、直玩、试玩，那么当 ROI 不好时，会无法判断问题来自：

- 产品本身。
- 首屏和首局体验。
- 素材承诺与游戏实际体验不一致。
- 流量版位不适合。
- 智投分配的流量结构变化。
- 广告变现点太晚或太弱。
- 留存周期不足。

所以第一阶段要先建立基准，再逐步扩变量。

## 6. 第一阶段：竞价广告 3.0 + 朋友圈 + 视频 / 图片

第一阶段建议围绕内部 Wiki 的冷启动路径来设计：

```text
广点通 / 腾讯广告竞价广告 3.0
  + 手动选择朋友圈版位
  + 视频 / 图片素材
  + 小预算稳定测试
```

这一路径的价值不是“马上放量”，而是让样本尽量干净。

第一阶段主要回答：

1. 是否能出量。
2. 首日 ROI 是否接近拼豆朋友圈参考水平。
3. 用户点击后是否真实进入游戏。
4. 用户进入首局后是否理解玩法。
5. 广告素材承诺和游戏首屏体验是否一致。
6. 首局通过、失败、复活、奖励、广告点结构是否健康。
7. 3 日、7 日 ROI 是否正常爬坡。

第一阶段不应该同时追求：

- 智投扩量。
- 视频号扩量。
- 激励视频扩量。
- 直玩 / 试玩结论。
- 多套游戏版本混测。
- 多个大 AB 实验同时混测。

第一阶段推荐小预算，预算不足时宁愿减少计划数量，也不要把预算拆得太碎。

## 7. 第一阶段的判断框架

第一阶段不是看“有没有马上回本”，而是看模型是否成立。

### 7.1 能不能出量

如果 ROI 目标设置后完全不出量，可能原因包括：

- ROI 目标过紧。
- 素材竞争力不足。
- 版位竞争激烈。
- 账户或计划学习不足。
- 产品还没有被系统识别出稳定人群。

这时不能直接判断产品不行，需要先看素材质量、出价策略、预算、目标设置和版位竞争。

### 7.2 首日 ROI 是否达到基础参考

内部 Wiki 给出的参考是：朋友圈视频 / 图片素材首日 ROI 如果能接近 7%-8%，说明有继续观察价值。

如果明显低于这个区间，应优先检查：

- 素材是否误导。
- 素材承诺和游戏首屏是否一致。
- 首屏 UI 是否劝退。
- 新手引导是否顺畅。
- 首关是否能快速进入状态。
- 广告变现点是否太晚或太弱。

### 7.3 3 日和 7 日是否爬坡

如果首日尚可，但 3 日、7 日爬坡弱，问题通常不只在投放，而在留存和内容结构。

重点看：

- 次日留存。
- 首局后目标感。
- 关卡节奏。
- 激励视频触发点。
- 失败、复活、奖励设计。
- 长线内容消耗速度。

### 7.4 30 日和 90 日是否支持长期模型

拼豆类 IAA 的最终问题不是“首日能不能回本”，而是 30 日和 90 日能否持续回收。

因此系统要从第一天开始保存长周期归因，不要只保存首日汇总。否则 30 日后无法回看这批用户来自什么素材、什么版位、什么版本、什么实验。

### 7.5 第一阶段决策矩阵

第一阶段看数据时，建议用下面这张矩阵做判断。

| 现象 | 更可能的问题 | 优先动作 |
| --- | --- | --- |
| 不出量 | ROI 目标过紧、素材竞争力不足、预算/出价不合理 | 先调目标、素材、出价，不急着改产品 |
| CTR 低 | 外层素材吸引力弱、题材不明确、静态视觉不够强 | 优先改素材表达 |
| CTR 高但启动低 | 点击后承接、加载、落地路径、误触点击问题 | 检查启动链路和素材误导 |
| 启动高但首局 ready 低 | 首屏、加载、授权、首页入口问题 | 优化首屏和进入首局路径 |
| ready 高但 10 秒存活低 | 首局第一眼劝退、引导太突兀、视觉压力大 | 优化首局开场和新手提示 |
| 10 秒存活正常但首次操作低 | 用户不知道点哪里、玩法表达不清 | 优化操作引导和反馈 |
| 有操作但有效操作低 | 规则理解成本高、误操作多 | 优化规则反馈和容错 |
| 首局通过低 | 首关难度、暂存槽、倒计时、失败条件不合理 | 优化首关结构 |
| 首局正常但广告完成低 | 广告点太晚、奖励弱、触发不足 | 优化广告点和奖励动机 |
| 首日尚可但 3/7 日弱 | 留存、目标感、长线内容、广告节奏问题 | 看次留、关卡节奏和长期内容 |

这张矩阵的意义是：第一阶段不急着追求“哪个素材最强”，而是先判断问题发生在哪一层。

## 8. 第二阶段：从基准走向扩量

朋友圈基准跑通后，才进入第二阶段。

第二阶段可以逐步尝试：

1. 视频号。
2. 其他微信站内版位。
3. 智投。
4. AIM+ 或后续智能投放能力。
5. 直玩素材。
6. 试玩素材。
7. 搜索场景扩量。
8. 更长期 ROI 模型。

第二阶段的原则是：一次只扩一个主要变量。

例如：

- 如果要测试视频号，就尽量保持素材方向和游戏版本稳定。
- 如果要测试智投，就不要同时大改素材和首局。
- 如果要测试直玩，就不要把直玩结果和朋友圈视频素材结果混为一谈。
- 如果要测试新游戏版本，就保留一条旧版本对照计划。

### 8.1 进入第二阶段的建议闸门

从第一阶段进入第二阶段，至少要满足一部分基础条件。不是所有条件都必须完美，但如果全部缺失，就不应该急着扩量。

| 闸门 | 说明 |
| --- | --- |
| 基准链路可解释 | 能看到从消耗、曝光、点击、启动到首局和广告完成的完整链路 |
| 朋友圈样本足够 | 核心计划有足够启动和首局 ready 样本，不是个位数样本 |
| 首日 ROI 不离谱 | 接近内部 Wiki 的拼豆朋友圈基础参考，或至少能解释差距 |
| 首局漏斗不崩 | 首局 ready、10 秒存活、首次操作、有效操作没有明显断层 |
| 广告点能触发 | 至少能看到复活、奖励、解锁等核心广告点之一形成完成 |
| 素材承诺一致 | 广告素材表达和游戏首屏/首局没有明显错位 |
| 数据能追踪长周期 | 同一批用户能继续追踪 3 日、7 日、30 日、90 日 |

满足这些条件后，再考虑视频号、智投、AIM+、直玩、试玩等扩展。

## 9. 智投、AIM+ 与自动化投放的定位

智投和 AIM+ 不应该被理解成“冷启动第一天就上”的万能工具。

它们更适合在以下情况下介入：

- 已经有一条相对干净的基准链路。
- 朋友圈视频 / 图片素材能跑出基础回收。
- 首局数据、广告点数据、留存数据没有明显断裂。
- 有足够素材和游戏事件数据给系统学习。
- 我们能承受更复杂的流量结构，并有能力复盘。

腾讯官方资料显示，adQ 3.0 体系和 Marketing API 3.0 是未来投放管理和自动化拉数的基础。2026 年小游戏 IAA 的七日变现 ROI 相关能力也在向 AIM+ 等智能投放方向演进。因此我们的系统不能只服务手动朋友圈测试，也要为后续智投 / AIM+ 留好数据接口。

官方来源：腾讯广告开发者专区 2026-01-15 通知提到，小游戏行业“七日变现 ROI”投放目标升级，普通广告将陆续不再支持通过 Marketing API 使用该目标，建议通过创建 AIM+ 智能投放项目使用该目标。  
<https://developers.e.qq.com/v3.0/pages/news/info/2601151>

但是会议要明确：

- 第一阶段用手动 3.0 朋友圈做基准。
- 第二阶段才逐步引入智能投放。
- 引入智能投放后，必须更重视 adQ 报表、游戏内事件、素材标签、版本和实验之间的关联。

## 10. 视频、图片、直玩、试玩分别验证什么

不同素材形态解决的问题不同。

| 素材形态 | 主要验证什么 | 适合阶段 | 风险 |
| --- | --- | --- | --- |
| 视频素材 | 外层吸引力、玩法表达、情绪承诺、首屏一致性 | 第一阶段开始即可 | 容易吸点击但误导用户 |
| 图片素材 | 静态视觉卖点、题材和画风吸引力、低成本对照 | 第一阶段可以小样本测试 | CTR 可能低，规模有限 |
| 直玩 | 正式玩法本身是否有广告级吸引力 | 基准后独立测试 | 和朋友圈视频/图片不是同一口径 |
| 试玩 | 专门广告试玩关卡能否更高效筛选用户 | 基准后独立测试 | 试玩体验可能和正式游戏承接断裂 |

视频和图片适合做朋友圈基准测试。

直玩和试玩更适合回答：

- 真实玩法本身有没有吸引力。
- 用户先玩到一点点内容后，进入正式游戏是否更稳定。
- 直玩/试玩带来的用户是否比视频/图片更接近真实玩家。

但直玩和试玩的结果不能用于替代朋友圈视频/图片基准。

## 11. 素材体系

素材不应该只是一个视频 URL 或图片 URL。我们需要建立自己的素材体系，因为腾讯 adQ 能记录素材和创意，但不会理解我们内部的玩法卖点、游戏版本、实验假设和复盘结论。

素材体系至少要覆盖：

1. 素材原文件。
2. 素材形态：视频、图片、直玩、试玩。
3. 素材方向：南瓜、人物、关卡、失败、完成、解压、奖励等。
4. 素材卖点：解压、简单、挑战、完成感、女友/剧情、奖励、失败复活等。
5. 素材对应的游戏版本。
6. 素材对应的首屏承接。
7. 素材对应的 AB 实验。
8. 素材标签和投放批次。
9. 素材生命周期：待测、测试中、可复用、放量、淘汰。
10. 素材复盘结论。

内部 Wiki 特别提到“投放素材标签”是广点通 3.0 中非常重要的实操点。同条件计划和素材批次测试，可能会受到素材标签和素材复用规则影响。因此我们的系统要同时处理两类标签：

- 腾讯 adQ / Marketing API 里的官方素材标签。
- 我们内部用于业务分析的素材标签。

两者不能混为一谈。

腾讯 Marketing API 也有官方素材标签能力，包括创建素材标签、获取素材标签列表、绑定标签素材关联关系等接口：

- `material_labels/add`：<https://developers.e.qq.com/v3.0/docs/api/material_labels/add>
- `material_labels/get`：<https://developers.e.qq.com/v3.0/docs/api/material_labels/get>
- `material_labels/bind`：<https://developers.e.qq.com/v3.0/docs/api/material_labels/bind>

## 12. 我们自己的投放实验体系

未来的投放系统不应该只是“同步 adQ 数据”，还要承载我们自己的实验设计。

每一次投放实验都应该明确：

1. 实验目的：产品诊断、素材验证、版位扩展、智投探索、版本验证、广告点验证。
2. 固定变量：投放方式、版位、人群、素材形态、游戏版本、AB 实验。
3. 变化变量：本轮到底只变了什么。
4. 样本要求：至少需要多少启动用户、首局 ready 用户、广告完成样本。
5. 判断周期：首日、3 日、7 日、30 日、90 日分别看什么。
6. 结果动作：继续、扩大、暂停、回炉产品、回炉素材、换版位、进智投。

第一阶段的实验目的应该以“产品和首局诊断”为主，素材只是控制流量质量的入口变量。

后续阶段再逐步切换到：

- 素材胜率。
- 版位扩展。
- 智投放量。
- 直玩 / 试玩验证。
- 游戏版本增长。
- AB 实验收益。

## 13. adQ / Marketing API 能提供哪些数据

adQ 是腾讯广告投放前台，Marketing API 是程序化接口。官方资料说明，ADQ 3.0 投放端基于 Marketing API 3.0 做广告创编和管理，并可通过 `apiDevTool=true` 查看页面对应的 API 请求。

因此正式系统应该走 Marketing API，不应该长期抓取 adQ 页面。

adQ / Marketing API 主要能提供：

| 数据类型 | 主要内容 | 对我们有什么用 |
| --- | --- | --- |
| 账号和权限 | 广告主、商务管家、可访问账号 | 确定能拉哪些账户 |
| 计划和广告组 | 投放方式、推广目标、版位、预算、出价、状态、投放时间 | 建立投放结构 |
| 广告和创意 | 创意 ID、动态创意、创意组件、状态 | 关联素材和广告表现 |
| 图片和视频素材 | 素材 ID、素材内容、素材状态、素材标签 | 自动化素材复盘 |
| 报表 | 曝光、点击、消耗、转化、ROI、小时/日报 | 对账和投放分析 |
| 资金 | 余额、今日消耗、资金流水 | 财务和预算控制 |
| 行为回传 | 游戏内转化事件上传腾讯 | 让腾讯优化模型学习 |

第一期建议优先接：

1. 账号和权限。
2. 计划。
3. 广告组。
4. 创意。
5. 图片/视频素材。
6. 日报。
7. 小时报表。
8. 资金/消耗。

第二期再接：

1. 转化上报结果。
2. 人群/定向报表。
3. 素材标签自动同步。
4. 直玩 / 试玩相关资产。
5. AIM+ / 智投专项数据。

## 14. adQ 不能替我们解决什么

adQ 能告诉我们广告怎么投、花了多少钱、拿到了多少曝光点击和转化目标，但它不能直接告诉我们用户进入游戏后真实发生了什么。

adQ 不能替我们解决：

- 用户是否真实进入游戏。
- 用户是否看到了首局可玩状态。
- 用户是否 10 秒内流失。
- 用户是否理解“点豆子 / 拼图”的操作。
- 用户是否完成有效选择。
- 首局失败是否过早。
- 复活广告是否触发。
- 胜利奖励广告是否触发。
- 用户是否看完广告。
- 用户是否因为首屏 UI、引导、关卡节奏流失。
- 哪个游戏版本、哪个 AB 实验影响了 ROI。
- 素材承诺和首屏体验是否一致。

这些必须由游戏内埋点和我们自己的数据系统解决。

## 15. 游戏内必须埋哪些数据

游戏内埋点不应该只记录“开始游戏”和“广告完成”。它必须围绕首局体验和 IAA 广告变现建立完整漏斗。

第一优先级：

1. 启动。
2. 进入首局可玩状态。
3. 首局 10 秒存活。
4. 首局 30 秒存活。
5. 首次点击。
6. 首次有效操作。
7. 教程完成。
8. 首局通过。
9. 首局失败。
10. 广告展示。
11. 广告点击。
12. 广告完成。
13. 关卡退出。

第二优先级：

1. 复活广告。
2. 胜利加金币广告。
3. 解锁槽位广告。
4. 商店入口。
5. 道具使用。
6. 暂存槽失败。
7. 倒计时失败。
8. 金币变化。
9. 奖励发放。
10. 退出时所在关卡和步骤。

每个事件都要能关联：

- 用户。
- 会话。
- 启动来源。
- 投放归因。
- 游戏版本。
- AB 实验。
- 关卡。
- 广告位。
- 时间。

这不是为了堆字段，而是为了能把 ROI 拆成真正可优化的漏斗。

## 16. 用户链路：PPID、openid、gdt_vid、click_id

用户链路需要同时满足两件事：

1. 能和腾讯归因链路对接。
2. 内部分析时不直接暴露敏感用户标识。

腾讯官方小游戏归因文档明确需要 `wechat_openid`、`wechat_app_id`、`clickid`，小游戏场景下 `clickid` 可来自 `gdt_vid`。`user_actions/add` 也要求小游戏场景使用 `wechat_openid` 或 `wechat_unionid`，使用 `wechat_openid` 时还需要 `wechat_app_id`。

因此建议：

- 安全服务端表保存原始 `wechat_openid`、`wechat_app_id`、必要时保存 `wechat_unionid`。
- 分析表使用内部生成的 `internal_ppid`。
- `internal_ppid` 由服务端基于 `wechat_app_id + wechat_openid` 或 `unionid` 生成，不由客户端生成。
- `gdt_vid` 和 `click_id` 作为广告点击归因链路保存。
- 如果 adQ 页面或 API 中存在运营所说的 `PPID`，必须先通过 `apiDevTool=true` 或 API 返回确认真实字段名和含义，再决定是否接入。

这里要避免一个误区：不要在未确认前把 `PPID` 当成腾讯官方标准用户 ID。当前公开文档中更明确的是 `openid / unionid / click_id / gdt_vid`。

## 17. 成本、ROI、LTV 的口径

腾讯官方报表能提供聚合消耗，例如日级、小时级、计划级、广告组级、素材级报表中的 `cost`。曝光/点击监测能提供曝光或点击 ID、计费类型、广告上下文，但公开监测字段中没有看到“单次曝光实际扣费”或“单次点击实际扣费”字段。

因此系统里要区分：

| 类型 | 含义 | 用途 |
| --- | --- | --- |
| 官方聚合消耗 | 腾讯报表/API 返回的消耗 | 对账、预算、ROI |
| 内部分摊成本 | 我们把聚合消耗按规则分摊到用户、会话、事件 | 分析每个漏斗节点的成本 |
| IAA 估算收入 | 根据广告完成、广告位、eCPM 或流量主数据估算 | 计算短期变现 |
| LTV | 用户在长期周期里的累计价值 | 判断 30/90 日回本可能 |

短期看：

- 每曝光成本。
- 每点击成本。
- 每启动成本。
- 每首局 ready 成本。
- 每首次有效操作成本。
- 每广告完成成本。
- 首日 ROI。

中长期看：

- 3 日 ROI。
- 7 日 ROI。
- 30 日 ROI。
- 90 日 ROI。
- 长留用户广告完成次数。
- 用户生命周期广告价值。

所有 ROI 都必须标明周期，不能只写“ROI”。

## 18. 素材、投放、游戏版本、AB 实验的关系

这个系统最重要的能力之一，是不要把问题归因错。

同一个投放结果，可能来自四类变量：

1. 流量变量：投放方式、版位、人群、出价、ROI 目标。
2. 素材变量：视频、图片、直玩、试玩、素材方向、素材承诺。
3. 产品变量：首屏 UI、首局引导、关卡节奏、广告点、奖励。
4. 实验变量：AB 分组、游戏版本、配置开关。

如果这些关系不记录，复盘时会出现：

- 素材表现差，其实是新版本首屏承接差。
- ROI 低，其实是广告点太晚。
- 首日不错但 7 日弱，其实是长线内容不足。
- 某个素材看起来好，其实只投到了更优质版位。
- 某个 AB 实验看起来差，其实流量来源不同。

因此每次投放都要能关联：

- 哪个 adQ 计划 / 广告组 / 创意 / 素材。
- 哪个素材方向和素材批次。
- 哪个游戏版本。
- 哪个 AB 实验。
- 哪个投放目的。
- 哪个判断周期。

这里不需要会议一开始就确定所有字段，但需要确认这是系统的核心设计目标。

## 20. 分阶段建设路线

### 第 0 阶段：会议确认和口径统一

目标：确认方向，避免系统一开始就做偏。

要确认：

- 第一阶段是否以 `竞价广告 3.0 + 朋友圈 + 视频/图片` 为基准。
- adQ / Marketing API 权限是否能开通。
- 素材标签和素材管理是否纳入一期。
- 游戏内埋点优先级。
- PPID / openid / unionid 的安全处理方式。
- 是否需要单独支持历史老系统数据查询。

### 第 1 阶段：最小闭环

目标：能回答“哪个投放计划/素材带来的用户，在游戏里表现如何”。

范围：

- adQ 基础报表导入或自动拉取。
- 游戏内启动、首局、广告完成埋点。
- 素材基础管理。
- 朋友圈基准测试看板。
- 计划 / 素材 / 首局 / 广告完成基础漏斗。

不追求：

- 全自动投放决策。
- 所有渠道全覆盖。
- 复杂人群分析。
- 完整长期 LTV 模型。

### 第 2 阶段：adQ 自动化

目标：不再依赖人工导表。

范围：

- Marketing API 应用和授权。
- 账号、计划、广告组、创意、素材同步。
- 日报和小时报表同步。
- 消耗和资金对账。
- 同步失败报警。

### 第 3 阶段：素材管理和复盘

目标：让素材成为可管理资产，而不是文件堆。

范围：

- 素材库。
- 素材标签。
- 素材方向。
- 素材批次。
- 素材和游戏版本关系。
- 素材复盘结论。
- 素材生命周期。

### 第 4 阶段：AB 实验和版本分析

目标：能判断 ROI 改善来自产品、素材、流量还是实验。

范围：

- 游戏版本维度。
- AB 实验维度。
- 配置开关。
- 版本对比。
- 实验对比。
- 流量均衡检查。

### 第 5 阶段：扩量与智能投放

目标：在基准链路成立后，支持智投、AIM+、视频号、直玩、试玩等扩展。

范围：

- 智投 / AIM+ 数据接入。
- 版位扩展。
- 直玩 / 试玩素材管理。
- 长周期 ROI 追踪。
- 投放复盘自动化。

## 21. 会议需要确认的问题

建议会议只确认方向，不要一开始陷入字段细节。

必须确认：

1. 第一阶段是否坚持少变量基准测试。
2. 第一阶段预算范围和样本要求。
3. 朋友圈视频 / 图片素材是否作为基准路径。
4. 智投、AIM+、视频号、直玩、试玩分别放到哪个阶段。
5. 素材系统是否作为一期核心。
6. 游戏内首局漏斗是否作为一期核心。
7. adQ / Marketing API 权限由谁申请和维护。
8. 原始 openid 是否只保存在安全服务端表。
9. 内部 PPID 如何定义。
10. AB 实验系统是否在一期就接入。
11. 看板优先做哪几张。
12. 是否需要兼容导入历史老系统数据。

## 22. 一期建议范围

如果要快速形成可用系统，一期建议只做这些：

1. adQ 数据导入或最小自动同步。
2. 朋友圈基准测试看板。
3. 游戏内首局漏斗埋点。
4. 广告完成埋点。
5. 素材基础库。
6. 游戏版本记录。
7. 基础 AB 实验记录。
8. 消耗和 ROI 对账。
9. 30 日、90 日追踪所需的归因保留。

一期不要做：

- 自动调预算。
- 自动关停计划。
- 全渠道智能决策。
- 太复杂的人群画像。
- 过细的字段治理。
- 过度兼容旧系统。

## 23. 成功标准

一期上线后，应该能做到：

1. 每天自动或半自动获得 adQ 投放数据。
2. 每条核心游戏事件能关联投放来源和用户。
3. 每个素材能看到投放表现和游戏内表现。
4. 每个游戏版本能看到投放质量差异。
5. 每个 AB 实验能检查流量是否均衡。
6. 每天能看到消耗、首局漏斗、广告完成、首日 ROI。
7. 3 日、7 日、30 日、90 日能够持续追踪同一批用户价值。
8. 会议能基于数据决定：继续投、改素材、改产品、扩版位、进智投，还是停测。

## 24. 风险和边界

### 24.1 数据不是越多越好

如果没有清晰实验设计，更多数据只会增加噪音。

### 24.2 不要过早自动化投放决策

当前阶段先做诊断和复盘，不建议一开始做自动调预算或自动关停计划。

### 24.3 不要把短期 ROI 当最终判断

拼豆类 IAA 需要长周期观察，短期 ROI 只适合判断基础质量。

### 24.4 不要让素材系统缺位

素材是投放和产品之间的桥。没有素材体系，就无法解释素材承诺、首屏承接、首局表现之间的关系。

### 24.5 不要把旧系统当成新系统蓝图

旧系统只能作为历史参考。新系统应该围绕 adQ、游戏埋点、素材、实验、长期 ROI 重新设计。

## 附录 A：docater1 只作为历史参考

`docater1` 老系统可以保留三类参考价值：

1. 它曾经做过哪些看板。
2. 它曾经有哪些字段命名容易混淆。
3. 它曾经有哪些数据链路值得验证是否还能导出历史数据。

- 老系统的字段命名。
- 老系统的页面结构。
- 老系统的计划 ID 口径。
- 老系统的素材绑定方式。
- 老系统的报表组织方式。

如果后续确实需要迁移历史数据，应该作为单独的数据迁移任务处理，而不是影响新系统主设计。
