# 侧边栏启动排查 D1（仅测试）

目录：`build/bytedance-mini-game-a-dev-launch-20261011-r2-diagnostic-d1`。

这是已验证 r2 的独立诊断副本，不是修复版或上线候选。1127 个原包文件的 SHA256 保持不变；只改入口脚本、项目名称/普通启动配置，新增诊断脚本。关卡、图片、游戏逻辑、SDK、DEV 云环境、存档编号、奖励逻辑均沿用 r2。r2 原目录没有修改。不要将 D1 上传提审。

## 手机操作

1. 导入 D1 目录，选择“普通编译”，点击“预览”，扫码进入；截图画面中的“排查版 D1 · 基于 r2 · dev”。
2. 从游戏“入口有礼”跳转到真实侧边栏，再点击游戏图标返回。无需换号或重复领取奖励。
3. 截取返回后的完整手机画面。若仍卡住，等约 20 秒，有诊断弹窗时一起截图；没有 D1 标识也照样截图。

这次不使用 021036 模拟模式。两种实际入口的画面用于对照版本和错误；标识缺失本身不能证明打开了旧包，也可能是引擎尚未运行或原生界面覆盖。

## 诊断范围

引擎画面就绪后显示版本、冷启动/回前台、侧边栏/其他入口、场景值、当前游戏场景和最近启动阶段。记录最近六条错误，画面展示最近两条。启动错误或长时间没有诊断画面时尝试原生弹窗；不依赖电脑调试连接。原生系统遮挡、JS 进程被终止或平台未运行这个包时，诊断无法保证显示。

诊断信息只在内存与本机画面中使用，不新增上传或持久存储。忽略启动 query 和错误对象中的身份/请求字段，并遮蔽常见凭证字段与 URL 参数；原有日志行为保留。诊断节点无触摸监听、无输入拦截组件。

本地已验证：前后台来源更新、错误观察器、脱敏、原生弹窗后备、换场景重建、独立相机、有限错误记录；生成包入口执行顺序、全部产物哈希、所需 Cocos 导出、26 项图集资源解析、广告回调/Spine/WASM检查通过。平台和渲染测试使用模拟对象，手机实际显示与侧边栏失败原因待本次实测。

实现：`scripts/package-douyin-startup-diagnostic.js`、`scripts/runtime/douyin-startup-diagnostic.js`。重复运行拒绝覆盖 D1；构建依据的 r2 源包/原始配置变化会停止。验证记录在 `.planning/douyin-dev-launch-20261011/diagnostic-d1-package.json`。
