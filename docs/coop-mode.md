## 已实现的规则

- 合作关卡列表与主页合作图鉴采用相同解锁状态：未获得图鉴的图案灰显，已获得的图案彩色；灰色图案仍可发起合作。

- 合作关卡、广场、参与记录和参与人员列表采用纵向滚动加载，滚动到底部追加下一批，不显示分页按钮或页码；参与记录入口固定在合作页右上角。

- 游戏顶部显示「合作模式」。棋盘展示整图：发起者只拼左半，右半显示灰色图案并覆盖遮罩；合作者看到左半已归位且为彩色，只拼右半。另一半为不可交互的展示，随棋盘缩放和移动，不参与本人的道具、完成判定与回放。

- 像素大厅进入「合作拼图」，专属 10 张图，整图 1894–2500 颗豆豆，左右严格等分。
- 发起者先完成左半，可以邀请好友、群聊，或发布到游戏内合作广场。
- 同一邀请允许多个合作者分别拼右半，各自记录完成状态，互不覆盖。每条完成关系始终是发起者加一位合作者。
- 左半与某位合作者右半均完成后，两人得到完整图鉴。之后其他合作者完成也会获得图鉴；发起者按图案去重。
- 发起者可以查看参与者完成状态、成功这次的有效游戏用时和完成时间；列表支持分页。
- 每人最多保留一个正在发起和一个正在协助的任务。发起者左半完成后仍保留任务，直到首位伙伴完成。
- 不额外扣体力，不发金币；倒计时、道具与复活采用上方新版规则，暂停、后台和等待保存不计入有效拼图时间。
- 只在完成时提交结果，未完成则不保存进度，不支持断点续玩。
- 云端依据一次性操作回放判定完成，使用平台 OPENID，客户端不能直接指定奖励或完成状态。

## 文件与生成

客户端入口为 `Core/GameCtrlModules/CoopModeModule.ts`，界面为 `Core/Panels/CoopPanelController.ts`，存档与云调用为 `Core/CoopServiceMgr.ts`，路径均位于 `assets/Scripts/`。

关卡真源与主线统一为 `assets/LevelData/coop_level_1.json` 至 `coop_level_10.json`，清单为 `assets/GameAssetsBundle/coop-manifest.json`。`tools/generated_levels/coop-original-10/` 仅保留预览和验证报告。执行以下命令同步合作云函数规则及关卡部署镜像：

```sh
npm run coop:build
npm run test:coop
```

修改共享 PCH 或回放规则后，也需运行现有 `npm run pvp:bot:build`，避免好友对战云端镜像与客户端不一致。本次已同步本地镜像，包含工作区此前已变更的关卡镜像，不代表上传。
