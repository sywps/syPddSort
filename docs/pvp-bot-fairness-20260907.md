# PvP 机器人难度修正与验收

日期：2026-09-07。范围：本地预览与微信云函数源码，不包含自动打包/部署。

## 已修改

- 删除本地固定 65 秒通关和服务端按评分随机指定终局的曲线。
- 共享 `PvpBotReplay.ts` 调用现有 `BoardModel/PchConveyorRules`，按真实关卡数据选块、入传送带、归位；终态由规则产生。未复制另一套棋盘规则。
- 按棋盘格数、颜色数、隐藏评分决定思考节奏；前 5 局减 250 分、连败每次减 100 分且至多减 300 分。整场轨迹创建后固定，不动态操控胜负。
- 对手缩略图与百分比共享真实已完成格增量；按最多 2 秒批次发送，不能提前显示未来格子。
- 本地先完成对手生成再扣预览门票；缺关卡直接报错。云端新版客户端关卡 hash 不一致时，扣体力/门票前拒绝。
- 新排位将对手评分单独冻结，修正公开资料不含评分导致结算回落到 1200 的问题。
- 云端连败持久化，本地仅当前会话记录；重复结果不累计，好友对局不改变排位连败。
- 开发测试录像默认不能进入生产真人匹配池，除非明确打开开发种子开关。

## 自动验证

`npm run test:pvp` 包含共享生成副本一致性、TypeScript 检查和 9 组测试。

- 对 205 个实际关卡逐个生成新手对手，独立重放记录的点击；校验选块合法、移动数量、传送归位颜色、每个格子的完成时间、终态、进度与缩略图一致。
- 额外覆盖 700/1800/3000 三档评分、多个种子，确定性、无效关卡拒绝、内容 hash 差异和保护评分上下界。
- 对真实云函数入口使用内存数据库验证：新手评分 950 冻结、按 950 结算而非默认 1200、重复提交不累计连败、下一场降难度、好友赛不改变保护、资源不一致不扣费。
- 原门票、异步好友、恢复、排行榜契约、大厅、像素玩法路由及资产同步回归通过。
- 校验发现并修复了浮点累加传送距离引起的一帧差异，现以整数毫秒计算距离。

最终新手固定种子集结果：205 关中 3 次通关、202 次超时、0 次传送带死锁；这是策略在关卡时限内的通关统计，**不是玩家胜率**。本机单场生成最大约 2.17 秒，不代表云函数冷启动或低端手机耗时。策略目前偏保守，需要上线灰度数据继续标定，不能承诺 50% 胜率。

同一 `sample1` 种子的第 3 关：1200 分新手对手实际 274.5 秒通关，2400 分成熟对手 199.75 秒通关；第 1 关 1600 格的该新手对手在 300 秒超时、完成 63.5%。没有强制所有棋盘都在同一时间通关。

## 时钟、兼容及上线边界

- 浏览器截图检查：旧标签出现模块解析错误；新开 7456 预览标签可以进入像素 PvP，并显示进度/缩略图，但仍在 65.0 秒按旧逻辑结算。检查 Creator 当前 `temp/programming/.../preview/chunks` 也仍含旧 `opponentTargetMs: 65000`，确认预览编译产物未刷新。**本轮不能把该截图作为新版运行验收**。需要 Creator 重新编译/刷新脚本后再测，不通过手改缓存伪造通过，也未强制退出用户的编辑器。
- 当前机器人传送用保守的 1 倍速、50ms 时步、半圈出口，不与场景几何和飞行动画逐帧等价；玩家倍速仍然只影响自己的传送带。真人录像服务端全面重放反作弊不属于这次修正。
- 旧 active match 不改写、不退票、不清空，沿用原冻结对手直至结算/10 分钟过期。修正用于新建对局。
- 旧客户端未传关卡 hash 时仍保留兼容能力；必须协调客户端和云函数版本，才能获得新版资源检查和本地行为。
- 先运行 `npm run pvp:bot:build` 和 `npm run test:pvp`，部署整个 `cloudfunctions/pvpService`（必须包含 `bot-runtime` 的四个模块及关卡 JSON）；再使用项目原有流程更新客户端。共享目录约 1.9MB，不需新增数据库集合。
- 本轮未打微信包、未部署云函数、未改生产玩家数据、未提交或推送 Git。正式环境仍需部署后做设备验收，尤其冷启动时间、原关卡资源版本、缩略图、连败保护及重复结算。
