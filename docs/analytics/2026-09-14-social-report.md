## 刷新方法

在项目根目录运行，沿用现有运行时 CloudBase 认证环境，不在文件或日志中保存凭证：

```sh
npm run analytics:social -- --date 2026-09-14
npm run analytics:social -- --date-from 2026-09-03 --date-to 2026-09-14
npm run test:analytics-social
```

输出位于 `artifacts/cloudbase-daily-report/<日期>/social_summary.json`。仅导出聚合值，不输出 openid、昵称或个人记录 ID。为正确关联跨日记录，任务读取观察终点前的历史记录，使用时间区间递归切分规避单次查询上限；不是增量任务。日期范围上限90天。

来源缺失、权限失败、格式或关联异常时，相应玩法显示不可用，命令返回非零；不会把失败伪装成零。另一玩法查询成功的结果可以独立显示。主线日报不存在时也能查看合作与 PvP。

## 合作口径

- 来源：`coop_posts`、`coop_runs`。
- 发起图：本日 createdAt 的合作图，按图去重。
- 新参与用户：本日创建个人记录的用户去重，含发起者和协作者；不是全部活跃用户。
- 当日完成：completedAt 落在本日的个人记录，可含前日创建。
- 队列完成率：本日新建个人记录中，截至本日观察终点已完成的比例。
- 整图达成：发起者完成且至少一名协作者完成；不要求同时在线。
- 不用当前 published、creatorDone 等可变标志反推历史发布状态。

## PvP 口径

- 来源：`pvp_matches`、`pvp_settlements`。
- 按真人历史回放、机器人、好友挑战拆分，并提供关卡明细。
- 发起用户按本日创建对局的 A 方去重；没有接受好友挑战时间戳，不宣称覆盖全部参与 UV。
- 已结算对局要求全部实际参与者截至观察终点都有结算；部分结算单独计数。
- 胜率＝真人胜结算人次÷真人胜负平结算人次。机器人和历史回放对手不计为当天真实活跃用户。
- 当日结算按 settledAt 归日，可含前日创建对局；不要与本日新对局直接作分母。
- 过期未结算仅按 expiresAt 和结算记录判断，不等于主动退出或明确失败。

## 缺失数据与解释边界

分享曝光/点击、匹配请求成功率、失败和退出原因、可归属广告 IPU、D1 留存：数据不可得。需要专用事件与合作记录/对局 ID 关联后再分析，不从普通关卡广告或通关表推算。

历史 theme 事件可能包含排位；本次没有回溯剥离普通像素拼图旧口径，模块 UV 不可相加。小样本只用于观察；20名用户不代表 AB 样本充足。

当前导出仅服务端记录统计，不能据此确认流量是否测试用户，也不表示当前线上客户端版本已经验证。
