# 微信全国排行榜诊断包 D1

本包用于比较“面板资源”“真实请求”“列表与头像渲染”三个阶段，帮助缩小内存上涨范围。它不会自动试玩，也不保证一次云测就能找到根因。操作仍由云测探索、平台支持的脚本或人工完成。

## 使用哪个目录

本次交付唯一根目录：

`D:\code\xyx\syPddSort\artifacts\wechat-diagnostics\leaderboard-d1-20261019-final`

在微信开发者工具中导入以下 **package 目录**，不要选其下的 minigame。AppID 沿用 `wxcacf359488bc4db6`，CDN 沿用 A。

| 模式 | 相对交付根目录的导入路径 | 点击全国榜后的行为 |
|---|---|---|
| full | `full\package` | 原有全国榜请求、列表、头像及关闭流程，附加观察器 |
| panel | `panel\package` | 加载原面板和美术，跳过此次打开触发的排行榜初始化与数据加载，显示“未发起排行榜请求” |
| data | `data\package` | 加载同一面板，执行原有进度提交、真实全国榜请求及适用的好友头像资料合并；跳过列表和自身条目渲染，显示返回项数 |

panel 不会关闭其他启动流程的后台网络或云初始化。data 包含面板资源，并非完全不加载 UI 的网络测试。好友排行不在这次对照范围内；点击好友页会提示并记录该次操作无效。

原基准仍在 `artifacts\wechat-baselines\20261016-172522-A\package`，未改动。其 project.config.json 早于本次任务已有设置变化，已在诊断清单中记录原始与当前哈希，未擅自回退。远程 CDN 和云榜数据未冻结，比较时仍要检查设备、账号和榜单内容。

同级没有 `-final` 后缀的目录属于制作过程记录，请勿上传。

## 先做这一轮

1. 先导入 `full\package`，在开发者工具预览，再用真机确认能正常启动、到达首页，并出现 `D1 full` 红色两行诊断文字。沿用能进入首页的测试账号；本包不会改玩家存档或跳关。
2. 先选已有明显上涨的 P30 Pro 或 Mate 30 一台设备。首页停留30秒，记录打开前内存；打开**全国榜**，等加载结束后再停留15秒；关闭，首页停留15秒。先重复3轮确认现象；需要判断累积增长时再做10轮。
3. full 能复现后，分别测试 panel、data。每个模式都结束小游戏进程再启动，使用同一设备、微信版本、账号、相同操作和尽量相同榜单数据。进程重启不等于清除文件缓存；三包应采用一致的缓存条件。不同模式不要在同一进程热切换。
4. 保留每轮打开前、打开后、关闭后1/5/10秒的云测内存曲线、录像/截图与日志。记录 total、native、graphics；不要把画面中的 N/T 当作 MB。

现有微信云测试仍可用于最终验证。先完成上述 full 真机预览，再由你上传对应体验版、提交单设备云测。测试单备注中写清 `rank-d1-20261019-full/panel/data` 和版本，避免体验版覆盖后混淆三次结果。三个项目沿用相同 AppID，开发者工具可能复用打开的项目；每次确认当前目录和画面模式再上传。

若使用智能探索，必须从录像确认它确实打开全国榜、等待返回并关闭。没有走到该操作的测试不算覆盖。平台自定义脚本格式尚未取得，本文不给未经验证的云测 API 或虚构脚本；以上动作顺序可作为录制/脚本的用例规格。

如果15秒仍在“加载中”，保留画面和日志，记作未完成请求；不要为了凑轮数快速关闭再打开。出现诊断文字“异常”、`diagnostic.failed`、`test.incomplete.closed-during-request` 或 `test.invalid.friend-tab` 时，该轮不能用于阶段对比。

## 证据在哪里

每个阶段输出 `[PDD_RANK_DIAG]` JSON 日志，包含毫秒时间戳、轮次、阶段耗时、可观察节点/纹理/资源数量、面板资源 owner 数、头像调用分支数量，以及关闭后延迟观察。定时器延迟只提示主线程调度受阻，不能单独判定卡死。

红字中的时间为 UTC，末尾带 Z；北京时间加8小时。N 为场景节点数，T 为可观察纹理数。纹理像素按 RGBA8 估算的字节数不是实际显存或完整进程内存；不可见的原生分配和引擎内部缓存可能不在计数中。JS 堆接口不支持时明确记 null。

本地日志文件：`wx.env.USER_DATA_PATH + '/pdd-rank-diagnostic-d1-full.jsonl'`，panel/data 对应替换后缀。每模式只保留最新启动会话，上限512 KiB；内存中保留最近1200条事件，超限状态可以读取。每次重启前先导出需要保留的日志。

在开发者工具**游戏主域**控制台运行：

```javascript
globalThis.__PDD_RANK_DIAG__.state()
```

查看模式、接入是否失败、storage 状态、事件和文件路径。再运行：

```javascript
globalThis.__PDD_RANK_DIAG__.readLog()
```

复制返回文本保存为对应模式的 `.jsonl` 文件。需要当前资源快照时使用 `globalThis.__PDD_RANK_DIAG__.snapshot()`。不支持文件读取会明确抛错，不生成假日志。

远程云测是否允许下载沙箱文件需要在当前平台页面核实；本包不能保证自动取出云设备文件。平台能导出的控制台日志、录像及内存曲线先保留。如果平台不提供详细日志下载，只能先按画面阶段和曲线比较；需要精确阶段记录时，用可调试真机复测并导出本地文件。

日志只保留条目数量及本地比较指纹，不记录玩家姓名、标识或头像地址。指纹用于发现内容差异，不是内容完全一致的数学证明。`rank.cloud.not-covered` 或 `source=local-preview` 表示没有覆盖真实微信云榜；真实云榜返回0条也没有覆盖批量头像压力。

## 怎么判断下一步

| 对照现象 | 下一步检查范围 |
|---|---|
| panel 已出现明显上涨 | 面板/图集加载、实例化与底层纹理分配；进一步核对加载前后资源及驻留策略 |
| data 明显高于 panel | 云初始化、进度提交、榜单返回处理或好友头像资料合并；按阶段日志继续细分 |
| full 明显高于 data | 列表节点、普通 URL 头像及装扮头像渲染；下一轮再隔离头像分支 |
| 首次上涨，重复开关后保持平台 | 可能是缓存或分配器保留；结合对象引用和后续稳定值判断，不能直接叫泄漏 |
| 每次关闭等待后仍持续阶梯上涨 | 更支持累积保留的怀疑；仍需定位对象/资源与释放链路 |

以上均是排查方向。单次峰值、不同账号或不同榜单的两次结果，不能直接相减归因。
